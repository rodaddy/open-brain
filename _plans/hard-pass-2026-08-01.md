## Scope and honest sizing

Five real hooks exist (`stop`, `session_end`, `subagent_stop`, `post_compact`,
`session_start` canon-only), the spine, watermarking, and the #420 cutover. The
in-process recording-lane layer is already dense (`test_capture_hooks.py`
covers all five at the composition boundary). Adding more fake-transport tests
would be coverage theater. **The entire value of this pass is the live-DB round
trip and the shape inversions that only real Postgres can expose.** Every item
pins a named carried-UNVERIFIED risk; nothing is added for a percentage. No new
bound, cap, or truncation anywhere — a number in a test is an input size.

Before this pass only `deliver_new_turns` and `run_stop` had live coverage.
`run_session_end`, `run_subagent_stop`, `run_post_compact`, and
`run_session_start` (canon) were proven against in-process fakes only — the
carried-UNVERIFIED set this pass closes.

## The write target — non-negotiable

Playground DB `open_brain_local_play` on `127.0.0.1:3101` is the ONLY write
target. Never the live dogfood DB (`open_brain_local_20260724`, :3100), never
core01. Test sessions/turns use `uuid4()` ids, so they never collide with clone
data or each other; all writes are INSERT-only. Playground data is never merged
back.

## The items — as run

Each: risk pinned → command/evidence → result.

### Item 1 — `run_session_end` releases a real server session slot (live)
**Risk:** `session_end` send proven only against in-process fakes; slot
exhaustion (`DEFAULT_MAX_SESSIONS=100`, `src/transport.ts`) is the failure
`SessionEnd` exists to prevent.

**Server-slot observability, resolved live:** the MCP session slot is an
in-memory `Map` in `src/transport.ts` (`sessions`, freed on the closing
`DELETE`), NOT a DB row. The `sessions` table in Postgres is the durable
session-memory store (summaries/tiers), not the transport slot allocator. The
local single-process service exposes no `sessions.size` on `/health` (the
`workers[]` array is core01-only). So there is no remotely queryable slot count
on the playground. The DELETE-is-issued proof already lives in-process
(`TestStartupFailureReleasesTheSessionSlot`, scripted server). The live delta
this item proves: `run_session_end` drives the REAL client through
`initialize → start_session → DELETE` and the server accepts the whole
lifecycle (`returns True`), while writing NOTHING — no `ob_raw_turns` row for
that session. The `session_id=None` no-op path stays in-process (no network).

New file: `tests/test_capture_session_end_live.py`.

### Item 2 — `run_subagent_stop` round-trips a subagent transcript under its own watermark key (live)
**Risk:** subagent send proven only against fakes; the per-subagent watermark
key (`session_id:agent_id`) must not collide with the parent `Stop`'s key across
a real send.

Evidence: `result.delivered == 1`; psql confirms `ob_raw_turns.content` for the
subagent `turn_uuid` is the exact subagent text, whole; the watermark advanced
under `session_id:agent_id` while the bare parent `session_id` key stayed `0`.

New file: `tests/test_capture_subagent_stop_live.py`.

### Item 3 — `run_post_compact` records the summary whole, and `prompt_id` dedup is stable across a re-fire (live)
**Risk:** (a) post_compact send proven only against fakes; (b) `prompt_id`
stability as the dedup key across a re-fired PostCompact is unproven. The
capability reuses `prompt_id` as `turn_uuid`, relying on server
`UNIQUE(namespace, turn_uuid)`.

Evidence, driven by the real fixture `PostCompact.json` with a `uuid4()` session
and a known `prompt_id`:
- First call `True`; psql: exactly one row where `turn_uuid = prompt_id`,
  `content` byte-identical to `compact_summary` (`len(stored) == len(given)` AND
  `stored == given`).
- A large summary padded past 200,001 chars proves no `MAX_CONTENT_CHARS`
  ceiling on this path.
- Re-fire same `prompt_id` → psql count for that `turn_uuid` stays exactly 1
  (dedup stability).
- Re-fire changed `prompt_id`, same text → two rows (the documented dedup
  boundary: dedup keys on `prompt_id`, not content). Recorded as an observation,
  not a failure. Whether a real harness re-fire assigns a fresh `prompt_id` per
  compaction is a residual to confirm against harness behavior — see
  `_plans/rewrite-gotchas.md` open observations.

New file: `tests/test_capture_post_compact_live.py`.

### Item 4 — `run_session_start` reads a real canon pack, canon-only, whole (live)
**Risk:** canon injection proven only against the `CanonPackReader` fake. The
real `agent_context_pack` contract — honors `requested_sections`, returns canon
tiers, does not leak episodic sections by default — is untested end to end.
Wrong sections is the "back-history poisons the next task" failure the ruling
forbids.

Evidence: the default (`profile_guidance`, `process_guidance`, `repo_facts`),
`repo=open-brain`, against the real server returns a pack whose `sections` keys
are a SUBSET of the three canon tiers — assert NO `working_set`,
`durable_memory`, `durable_lane_context`, `recovery`, `pointers`, or
`candidate_memory` key. `source="compact"` also returns canon. Empty override
→ `None`. A widened override surfaces the extra section live.

New file: `tests/test_capture_session_start_live.py`.

### Item 5 — the resume shape (watermark→EOF), live
**Risk:** the suite reads offset-0 more than it resumes, inverted vs the live
`Stop` shape which is always watermark→EOF. Offset-0 is the bulk app's shape;
`test_capture_hooks_live.py` delivers once from offset 0 and never resumes.

**Not a new file — a live resume test added beside the existing Stop live test.**
Evidence: first `run_stop` advances the watermark; append new lines; second
`run_stop` on the same session delivers ONLY the appended turns
(`delivered == len(appended)`), and psql confirms only the new `turn_uuid`s
appeared between calls. The skipped-hook self-heal is proven live: fire, append,
fire → nothing lost, nothing duplicated. Offset-0 unit tests are NOT deleted —
offset-0 is the legitimate first-read and the bulk app's shape; the correction
is that the LIVE suite now leads with resume.

Added to: `tests/test_capture_hooks_live.py`.

### Item 6 — the LAN client path from a second machine (live, cross-host) — BLOCKED
**Risk:** the LAN client path (the plan's premise: a second machine at
`http://10.71.1.20:3100`) is untested end to end.

**Resolved this session: there is no disposable LAN target, and the premise is
factually wrong.** `10.71.1.20` is THIS machine's own LAN IP
(`ipconfig getifaddr en0` = `10.71.1.20`). `:3100` on it is the real dogfood
service (`open_brain_local_20260724`) — Claude's real memory, a forbidden write
target. The playground on `:3101` is loopback-bound (`OPEN_BRAIN_BIND_HOST=
127.0.0.1`), so it does not answer on the LAN IP at all. The repo stack notes
say there are exactly two hosts (this machine + core01 at `10.71.1.21:3100`);
`10.71.1.20` is not a distinct third host.

The only code delta Item 6 would add over the loopback live tests is a
non-`127.0.0.1` IP literal plus `allow_insecure_http` for an `http://` endpoint.
But `allow_insecure_http` is ALREADY exercised: every existing live test uses
`http://127.0.0.1:3101` (non-TLS, insecure http). A non-loopback IP literal is a
routing/DNS property, not client-code behavior, and there is no genuine second
machine to prove real cross-host reach. Rebinding the real-memory-adjacent
service or writing to the real DB to manufacture a result would violate the
non-negotiables.

**Item 6 = BLOCKED, no disposable LAN target.** The LAN risk is carried forward
UNVERIFIED. Closing it needs an actual second host running a disposable
Open Brain reachable over the LAN — an infrastructure task with its own scope,
not a write to this host's real memory.
