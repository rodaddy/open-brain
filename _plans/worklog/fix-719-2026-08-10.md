## The defect (RUNNING — reproduced in this lane's own worktree)

`core.hooksPath = _githooks` displaces the operator's global
`core.hooksPath = /Users/rico/.config/git/hooks`. Git consults exactly one hooks

```

error: cannot find a hook named pre-commit      # exit 1
```

RUNNING, in the lane worktree, before any fix. `.git/hooks/pre-commit` exists
and is executable and is *unreachable*, exactly as #719 states — git ignores

exists to restore the displaced global gitleaks hook; it has never run.

## Sweep of the WHOLE displaced set (round-30 lesson: enumerate, do not assume)

Displaced directory `/Users/rico/.config/git/hooks/` contains exactly two
executable hooks. RUNNING (`ls -la`, executable-bit test):

| displaced hook | `_githooks/` provides | controls displaced |
|---|---|---|
| `pre-commit` | **NOTHING** | gitleaks staged scan; LAW #8 protected-branch commit block; formatter+restage; doc generators |
| `pre-push` | `pre-push` (repo's own) | **gitleaks push-range scan; default-branch push guard (`ALLOW_DEFAULT_PUSH`)** |

The `pre-push` row is a SECOND live gap the issue did not name, found only
because the charter required sweeping the whole set rather than fixing
`pre-commit` alone. RUNNING evidence: `rg -n "gitleaks|ALLOW_DEFAULT_PUSH"
_githooks/pre-push` returns zero hits. The repo's `pre-push` runs typecheck,
tests, and package gates — it never scans for secrets and never guards the
default branch. So the override dropped secret scanning from BOTH ends of the
commit path, not one.

That is the audit's lesson landing twice in one directory: an override
replaces, never overlays, and the replacement is only as complete as someone
checked.

## Direction

Fix at the owning boundary = tracked `_githooks/`, per `install.sh`'s own
principle ("the tracked directory must BE the hooks directory"). Two shipped
hooks:

1. `_githooks/pre-commit` (new) — restores the displaced controls, announcing
   each stage (AGENTS.md "nothing is adjusted silently").
2. `_githooks/pre-push` — gains the displaced gitleaks push-range scan and the
   default-branch push guard, ahead of the expensive phases.

Delegating by exec'ing the global hook was REJECTED: the global path is a
machine-specific absolute string, it is untracked and unreviewable, it is absent
in CI and in every other clone, and #711's whole finding is that an absolute
per-clone path in this repo's hook layer is the root enabler. The controls are
therefore reimplemented in tracked files, and the check asserts the CONTROLS,
not the delegation.

## Fixture defects found and fixed (round-30: the fixture must express the defect)

Four of these produced a RED that was NOT the subject failing. Each is recorded
because reading a false RED as a real one is how a working gate gets "fixed".

1. **The first canary was undetectable.** AWS's documentation key
   (`AKIA`+`IOSFODNN7EXAMPLE`) is deliberately allowlisted by gitleaks 8.30.1 —

2. **A false PASS on clause (f).** The push fixture lacked
   `contracts/parity-paths.txt`; the hook died reading it, the push was refused,

   the refusal to NAME the scanner rather than accepting any non-zero exit.
3. **Untracked scaffolding.** `_githooks/` copied into a fixture is untracked,
   so a later commit had nothing staged and exited 1 with "nothing added to
   commit" — a refusal from git, not from any gate.
4. **A defective CONTROL fixture for (j).** The stand-in displaced directory
   held a `post-checkout` that `_githooks/` never provides, so (j) went RED and
   the assertion was RIGHT. The control now mirrors exactly what `_githooks/`
