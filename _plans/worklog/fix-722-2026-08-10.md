## The fix

Three parts, mirroring the issue's done-means suggestion:

1. **Pin the fixture environment.** Both fixtures set `core.hooksPath=_githooks`
   immediately after `git init`, so the fixture is hermetic against the
   operator's global config and the hook under test reaches its own subject
   code. This is the one line the audit added by hand to prove the fixes intact.

2. **A HARNESS-ERROR guard, not a FAIL.** Before any clause runs, each check
   asserts the fixture's EFFECTIVE `core.hooksPath` is `_githooks`. A mismatch
   exits 3 (harness error), because a blinded fixture is not a statement about
   the subject. Round 30: the fixture environment must be able to express the
   defect.

3. **A parse failure is not a regression.** Each check now recognises the
   blinded state in the hook's own output and says so — "the hook REFUSED before
   reaching its subject" plus the refusal's first line — instead of emitting the
   original regression text. A parse failure and a wrong answer are different
   defects with different owners (round 29).

with no hooks is a POSITIVE pin, and it is the right one when the check's
subject is a different gate entirely.
